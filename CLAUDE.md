# prado-image

A PRADO 4 extension providing image container readers, metadata editing, and image codecs: JPEG, TIFF, PNG, WebP/RIFF, GIF87a/89a (animation, frames, palettes), AVI, ISO BMFF (HEIF/AVIF/MP4/QuickTime), and JPEG XL containers; EXIF (full TIFF/IFD engine, every DC-008-2026 tag (220 known tags: the spec's 212 plus the TIFF document/host and Windows XP* fields) through Exif 3.1 (CIPA DC-008-2026, spec linked from agents/README.md) incl. the UTF-8 field type, GPS, IFD1 thumbnails, Kodak APP3 Meta) with makernote decoding for 13 camera makers; DOM-backed XMP (full ISO 16684-1 value grammar, extended XMP in JPEG, PNG/WebP/TIFF carriers); the complete Photoshop 8BIM IRB; IPTC (IIM) records; JFIF/JFXX thumbnails; PrintIM; APP12 Picture Info; the Photoshop File Info 22-field sync layer; JUMBF/APP11 box metadata; Exif WAVE audio files; fully read-write ICC profiles (`TICCProfile`: every header field, typed tag reads and writes, profile-id digest) with a pure-PHP matrix/TRC color transform (`TICCTransform`) — reading and rewriting the container without re-encoding the pixels — plus the LZW/GIF-LZW/PackBits/horizontal-predictor codecs (`Prado\IO\Compression`) and dual GD/ImageMagick raster conversion (`TImageGraphics`).

## Mirror repository — keep in sync

- This repo and **[php-image](https://github.com/belisoful/php-image)** (`../php-image`) are **mirrors of one another**: the same library, customized for the PRADO framework, the sibling being a general standalone PHP library. They must stay **synchronized in features and function at all times** — a change here is not finished until the equivalent change lands in the sibling, and vice versa. That covers source, tests, coverage/branch gates, CI, and the `agents/` notes.
- Only the host adaptation differs; behaviour, structure, and file-for-file layout must not:

| Concern | prado-image | php-image |
|---|---|---|
| Namespace | `Prado\IO\Image\…`, `Prado\IO\Compression\` | `Belisoful\Image\…`, `Belisoful\Image\Compression\` |
| Class names | `T` prefix (`TEXIF`, `TTIFF`, `TGIF`) | no prefix (`EXIF`, `TIFFImage`, `GIFImage`) |
| Interfaces | `I` prefix (`IPrivacyScrubbable`, `IImageGraphicsLibrary`) | `Interface` suffix (`PrivacyScrubbableInterface`, `ImageGraphicsLibraryInterface`) |
| Base types | Prado's `TComponent`, `TEnumerable`, and the framework IO stream layer (`TStream`, `TLimitStream`, `Prado\IO\Compression\ICompressor`) | dependency-free equivalents: plain classes, class constants for enumerables, `Belisoful\Image\Stream\StreamIO`/`BinaryReader`, its own `CompressorInterface` |
| Exceptions | Prado's `TIOException`/`TInvalidDataValueException`/`TInvalidDataTypeException` with keys in `config/errorMessages.txt` | SPL only (`\InvalidArgumentException`, `\UnexpectedValueException`, `\RuntimeException`), messages at the throw site |
| Dependencies | `pradosoft/prado` (dev `^4.4@dev`); registers class map + error messages through `extra.prado` | `psr/http-message` only |
| Private spaces | `toReservedSpaceStream()`/`toFreeSpaceStream()` over the framework's stream decorators | `getReservedSpaces()`/`getFreeSpaces()` offsets; the caller windows the bytes |

- **Version numbers are the same in both repos.** Only a sub-fix component may diverge (`v0.0.0.x` — the trailing `x`); the `major.minor.patch` prefix always matches, so a feature that bumps the version here bumps it there too.
- When porting, translate names per the table above and nothing else: same classes in the same order, same method names and signatures, same test names, same invariants. If a feature genuinely cannot exist on one side, say so explicitly in both repos' notes rather than letting the two drift silently.

## Key facts

- Classes live under `Prado\IO\Image\`, `Prado\IO\Image\TIFF\`, `Prado\IO\Image\GIF\`, `Prado\IO\Image\ICC\`, `Prado\IO\Image\Meta\`, `Prado\IO\Image\Meta\Makernote\`, and `Prado\IO\Compression\` (PSR-4 `Prado\` → `src/`). This extension does **not** update the framework's `classes.php`; Prado3 short names come from `config/classMap.json`.
- `TEXIFTags`, `TMakernoteTags`, `TMakernoteTables`, and `TPhotoshopResourceNames` embed large fact tables (tag ids, names, enumeration lookups, maker header signatures) sourced from the public TIFF/EXIF/GPS specs and camera documentation; edit them like any source file (there is no build step), but keep entries factual and complete.
- EXIF rewriting pins the makernote value area at its original offset (`TTIFFTag::setPreserveOffset()`), so camera-internal absolute pointers survive; never break that invariant.
- TIFF files are read-write: strip/tile data rides `TTIFFTag::setExternalData()` (captured on parse, relocated on compose with the byte-counts pair kept in sync); `TTIFF::getImage()/setImage()` decode/encode the raster through the `Prado\IO\Compression` codecs, including the CCITT fax modes (`TCCITTFaxCompressor`). Decoding lives in `TTIFFRaster::toRgb()` — strips and tiles, chunky and planar, 1/2/4/8/16-bit, either fill order, and the bilevel/grayscale/palette/RGB/CMYK/YCbCr/L\*a\*b\* photometrics, all normalized to 8-bit RGB; the writer always emits 8-bit chunky RGB strips (or 1-bit bilevel for the fax modes). The TIFF 6.0 section-by-section status lives in `agents/working/TIFF6-coverage.md` (spec PDF linked from `agents/README.md`; local copy in the git-ignored `local/`).
- XMP property forms come from `TXMPSchemas`, not from the caller: `TXMP::setProperty()`/`addArrayItem()` consult it to write `dc:title` as a LangAlt and `dc:subject` as a `Bag`, and `TXMP::validate()` reports stored forms that contradict the schema. Extend that table when adding schema knowledge rather than special-casing names in `TXMP`.
- Every container is read **and** write for each carrier its format defines, and a setter must never accept data it will drop: JPEG (APP1/APP2/APP13 segments), TIFF (IFD tags), PNG (`iCCP`, `eXIf`, `iTXt` XMP, and the `Raw profile type 8bim` text chunk that carries the Photoshop IRB and so IPTC), WebP (`ICCP`, `EXIF`, `XMP ` with their `VP8X` flags), GIF (`XMP DataXMP`, `ICCRGBG1012`, comments, the NETSCAPE2.0 loop count). `TImageFile::hasIPTC()/hasICCProfile()` go through the accessors so a container can override them. Where a format has no carrier at all the setter **throws** rather than silently discarding: IPTC in WebP, GIF, AVI, ISO BMFF and JPEG XL, plus Exif and ICC in AVI and ICC in JPEG XL, whose profile lives inside the codestream. `TContainerReadWriteTest` is the regression guard for the whole matrix: `testEveryContainerRefusesTheCarriersItHasNoHomeFor()` drives every container against every carrier it lacks — getter null, `hasX()` false, a null accepted, a value thrown, and nothing written by the refusal — while each format's own section round-trips what it does accept. A new container joins both halves.
- GIF is read-write and animation-aware: `TGIF` walks the block stream into an ordered list of `TGIFFrame`s and `TGIFExtension`s (`Prado\IO\Image\GIF\`), and composes it back byte-faithfully. Frames are **authored, never coalesced** — the stored sub-rectangle, interlace flag, local colour table, delay, disposal, and transparent index are kept as read, because coalescing is exactly what loses them (measured: ImageMagick's coalesce/deconstruct path rewrites frame geometry, disposal, background index, and transparency). Two invariants matter: data sub-block *framing* is preserved, not just the joined bytes; and application-extension identities keep their exact case, so `XMP DataXMP` and `ICCRGBG1012` survive (ImageMagick lowercases them, and GD drops every extension along with all frames after the first). `TGIFFrame::setPixels()` raises the LZW minimum code size to fit the indexes; pixel data rides `TGIFLZWCompressor` and raster conversion goes through `TImageGraphics`, including `paletteQuantize()` for `setImage()`/`TGIF::fromImage()` (both keep every extension and replace only the frames). A third invariant: the `XMP DataXMP` packet is stored **raw**, not in sub-blocks, ended by `TGIFExtension::MagicTrailer` (258 bytes: 1, then 255 down to 1, then two zeros) — `TGIF::parseRawApplication()` special-cases it on read and `TGIFExtension::getIsRaw()` on write, because sub-block framing would eat one packet byte per 255 as a length. ICC rides `ICCRGBG1012` in ordinary sub-blocks; there is no IPTC carrier, so `setIPTC()` throws.
- PNG is animation-aware (APNG): `TPNG` reads/writes `acTL`/`fcTL`/`fdAT` as `TAPNGFrame`s (`Prado\IO\Image\PNG\`) over the generic chunk model — `getApngFrames()`/`setApngFrames()`/`addApngFrame()`/`fromApngImages()`, with `getApngFrameImage()` decoding a frame by rebuilding a standalone PNG from its data + IHDR colour fields. Frames are authored, not composited; a no-edit round trip is byte-faithful. `setApngFrames()` rebuilds the chunk region with **one ascending sequence number across every fcTL and fdAT** (the invariant a decoder validates) and sets the canvas from the frames' placed extents. Position-sensitive chunks (acTL/fcTL before IDAT, fdAT after, cICP/mDCv/cLLi before PLTE) are in `TPNG::ChunkOrder` so fresh authoring lands them validly. `setImage()` re-encodes to a still PNG (animation dropped).
- RIFF is nested, not flat: `TRIFF::parseChunks()` is one walker for the container body and for every `LIST` payload, so a list reads as a `TRIFFList` — a `TImageChunk` to whatever holds it and a chunk collection in its own right (AVI's `LIST hdrl`/`LIST INFO`, Exif WAVE's `LIST exif`). Children are materialized on demand, but **once materialized the payload is always recomposed from them**, so a child edited in place is never lost to a stale copy; the walker hands back the trailing bytes that are not a whole chunk and `TRIFFList::getData()` re-appends them, which is what keeps a rewrite byte-faithful. A **deferred** list stays an opaque `TImageChunk` — not parsing it is exactly what a lazy read is for — and `TRIFF::fromStreamLazy()` accepts either the bare `LIST` id or the qualified `LIST:<listType>` so AVI can stream `movi` past while still reading `hdrl` and `INFO`.
- RIFF has three header variants and `TRIFF` reads and writes each as it was found: **`RIFX`** is the same grammar with every size **big-endian**, carried into nested `TRIFFList`s so a rewrite is correct at any depth; **`RF64`** and **`BW64`** (the same structure under its ITU name) put the sentinel `0xFFFFFFFF` in a size and keep the real 64-bit value in a leading `ds64` chunk — one field for the container, one for `data`, a table for anything else. A sentinel resolves through `ds64` on read, and a rewrite **updates `ds64` to what it actually wrote**, leaving the sample count alone as an audio fact rather than a layout one. A 64-bit file with no usable `ds64` writes the real size instead of an unresolvable sentinel. `TRIFF::Signatures` is the accepted set; WebP and AVI still require plain `RIFF` in their own sniffs.
- AVI is a read-write metadata container (`TAVI`): `LIST INFO` tags, XMP in `_PMX`, and the `IDIT` timestamp, with privacy scrubbing by category; there is no TIFF/Exif, ICC, or IPTC carrier in AVI, so those setters **throw**. The media is never decoded. One invariant governs every write — **the `LIST movi` list never moves**, because `idx1` and any OpenDML `indx` address it: `TAVI::placeChunk()` appends a new chunk past everything, rewrites a chunk after `movi` where it is, and rewrites a chunk before `movi` **in its own slot whenever it fits** — the same length, or shorter with a `JUNK` chunk filling the remainder — and when it does not fit, vacating the slot to `JUNK`, **merging any now-adjacent padding**, and taking the smallest run of the file's padding that can hold it — padding is space already set aside, so filling it moves nothing — appending at the end only when no run fits. `TAVI::getCanRearrange()` is the **exception to the never-move rule**: when there is no OpenDML index and `idx1` is measured from `movi` rather than the file, every structure addressing the media provably survives a move, so the write is simply made and everything after it shifts (no padding, no append). A deferred media list proves nothing, so it does not qualify. BMFF keeps the conservative rule, its stills already having the provable `iloc` relaxation. Fitting has a floor: the remainder must hold a padding chunk's own eight-byte header, so a replacement that frees fewer than eight bytes has to move even though it is smaller (RIFF pads to even lengths, so that means a shortfall of two, four or six). Nothing an index addresses ever moves, so no index is ever fixed up.
- The ISO base media box grammar is shared, not per-format: `TBMFFBox` (`Prado\IO\Image\BMFF\TBMFFBox`) owns the 32-bit size, the `size == 1` 64-bit form, the `size == 0` run-to-the-end form, `uuid` user types, and depth-capped nesting, and `TJUMBFBox` builds on it with only what JUMBF means by those boxes. Which types hold children is format knowledge, so a subclass lists them in `ContainerTypes` — the base names none, which is exactly a flat JPEG XL container. A rewrite is byte-faithful, not merely valid: the **stored size form is kept** rather than re-encoded, and a container re-appends its **remainder** of trailing non-box bytes. Container-ness is **per instance**, not per type: a container stopped by `MaxDepth` or given bytes through `setPayload()` holds those bytes and writes them back untouched.
- JPEG XL is a read-write metadata container (`TJXL`) over the plain `TBMFFBox` grammar — JXL declares no container boxes, so it needs no subclass. Carriers: `Exif` (a four-byte big-endian offset to the TIFF header, honoured on read and written as zero), `xml ` (XMP), and `jumb` (JUMBF). ICC lives **inside the codestream** and there is no IPTC carrier, so both setters **throw**. Dimensions come from `TJXLSizeHeader`, which reads the codestream's bit-packed `SizeHeader`: bits are least-significant first within each byte **and a field's first bit is its low bit**, which is neither order the framework's bit reader offers, so that bit reading is deliberately local. `TJXL::getCodestream()` assembles the codestream from `jxlc`, or from the `jxlp` parts joined in index order with each part's four-byte index (high bit = last part) removed. Setting metadata on a **bare codestream (`FF 0A`) promotes the file to a container**, carrying the codestream verbatim into `jxlc` behind the signature and `ftyp` boxes rather than refusing the write, and new boxes land before the codestream. A `brob` box is Brotli-compressed and is **recognized but not decompressed** (PHP bundles no Brotli): such a carrier reads as absent and `getHasBrotliCarrier()` distinguishes that from empty, while writing a carrier removes the `brob` that stood for it so the file never holds two copies that disagree.
- ISO BMFF is a read-write metadata container (`TBMFF`) covering HEIF, AVIF, MP4 and QuickTime, told apart by the `ftyp` brand; `TBMFFFileBox` adds the container list and the fact that **`meta` is a FullBox** (four bytes of version and flags before its children — parsing it as a plain container reads them as a box length and desynchronizes the whole file). Two carriers: the Adobe `uuid` box (`BE7ACFCB-…`) that movies use for XMP, and `meta` **items** (`TBMFFItem` joins an `iinf`/`infe` description to its `iloc` location) that HEIF/AVIF use for Exif and XMP. **Nothing in the file ever moves**, because `iloc` extents and `stco`/`co64` offsets are absolute: a top-level box follows the AVI rule (in its own slot whenever it fits — exactly, or shorter with a `free` box filling the remainder, subject to the same eight-byte floor — else `free` over the slot, merge adjacent free space, and take the smallest run that fits before appending), and an **item's bytes are appended in a fresh `mdat` with its `iloc` extent patched in place** — possible because patching two numbers does not change `iloc`'s length (measured on a real libheif HEIC: two bytes change, `mdat` stays put). A rewrite is relative to the item's **base offset**, since libheif puts the whole address there and leaves the extent offset zero while others do the reverse. If a new offset or length would not fit the widths `iloc` already uses, the write **throws** rather than widening a field. Movie user data is read and written in **both** conventions: QuickTime text atoms under `moov`/`udta` (`[u16 length][u16 language][text]`) and iTunes tags under `moov`/`udta`/`meta`/`ilst`/`<key>`/`data` (`[u32 type][u32 locale][value]`, type 1 = UTF-8). `getUserDataValue()`/`setUserDataValue()` read either and write whichever the file already uses, falling back to the brand; removing clears both. `\xA9xyz` is the Location privacy entry. Resizing `moov` is guarded by `holdMediaInPlace()`: a free-space box after `moov` absorbs the difference, media straight after it means the edit is **undone and the write throws**, and neither means nothing addressed follows `moov` so it may grow. The ICC profile is read and written through the `colr` item property in `iprp`/`ipco`, associated to the primary item via `ipma` (non-essential); removing it renumbers every higher property index, and an `nclx` box states coefficients rather than a profile so it reads as none. The profile is written **in place whenever `ipco` can pay for the change out of a `free` property kept last in it** — padding goes last so no existing property changes index, and removal swaps the `colr` for a `free` box of the same length so its index stays occupied and nothing renumbers. A second shrink has no eight-byte floor, since the padding already exists; the trade is made against the measured change in the whole `meta` box, so the association a write adds or drops is paid for too, and an attempt that cannot be is undone. Only when `ipco` cannot pay does this fall back to the **one relaxation of the never-move rule**, and only where it is provable: resizing `meta` is allowed **only for a still**, where `iloc` is the complete set of absolute references and every one is corrected — a file with `moov`/`moof` is refused because `stco`/`saio`/fragment offsets address it too, and any refusal undoes the edit. The shift goes to whichever `iloc` field carries the address: the **base offset** when the table has one (libheif's layout), the extent offset otherwise. Items can be **created**, not only repointed: `TBMFF::addItem()` appends the `infe` entry, the `iloc` extent and an `iref`/`cdsc` reference saying the new item describes the picture (omitting that link leaves a reader unable to tell which image an `Exif` or XMP item belongs to), corrects every item location for the growth, then points the item at bytes appended in a fresh `mdat`. `setEXIF()` creates its item when the file has none, and `setXmpText()` on a still creates the `mime` item HEIF defines while a movie still uses the `uuid` box. An entry describes its item in sixteen bits, so a file already holding 65535 items is refused. Not modelled, and so refused: IPTC, which the format has no carrier for.
- Privacy scrubbing is metadata-wide and first-class: `IPrivacyScrubbable::clearPrivateData(int $types = TPrivacyCategory::All): int` is implemented by every carrier (`TEXIF`, `TXMP`, `TIPTC`, `TPhotoshopIRB`) and by `TImageFile`, whose fan-out reaches every carrier the container holds (getter/setter pairs) plus a `clearFormatPrivateData()` hook for format-only fields (JPEG comment/JFIF/JFXX/PictureInfo, PNG text chunks, GIF comments; TTIFF scrubs its live EXIF there since it has no `setEXIF()`). `TPrivacyCategory` (`Prado\IO\Image\`) is a `TEnumerable` of one bit per identifying category (`All` = -1) and its docblock tabulates what each flag removes per carrier. The per-category fact lists are constants beside each carrier — `TEXIF::PrivacyTags` ([group, id] pairs), `TXMP::PrivacyProperties` ([namespace, property]), `TIPTC::PrivacyDatasets`, `TPhotoshopIRB::PrivacyResources`; EXIF's directory-level categories (Location = GPS IFD via its pointer tag, MakerNote, Thumbnail = whole IFD1, Interoperability) are removed structurally and no IFD is ever created as a side effect. It **never** touches picture-describing fields (exposure/colour/dimensions) — a scrubbed file must stay a useful photo. The IRB redacts (not drops) its embedded IPTC, and the IPTC scrub replaces an existing mandatory envelope date (`DateSent`) with `TIPTC::ScrubbedDate` and re-derives an existing `EnvelopeNumber` from it (counted as removals) because `validate()` would otherwise re-stamp today's date on the next `toBinary()` — replaced, never minted: a record set with no envelope is not given one. A scrub must be idempotent and must not mint new identifiers or timestamps. When adding a tag/property that carries identifying data, add it to the carrier's list under the right category; `TEXIFPrivacyTest`/`TPrivacyScrubTest` enforce per-flag isolation for each carrier and that **every** container's scrub reaches every carrier it has — including AVI, both halves of ISO BMFF (a movie's `udta` user data and a still's `meta` item), and JPEG XL, which has no format-only identifying field of its own so the carrier fan-out is the whole of its scrub.
- Private spaces (maker notes, private IFDs) bridge to the framework's reserved-space stream decorators: `TEXIF`/`TTIFF` expose `getReservedSpaces()` (the pinned `[offset,length]` ranges within `toBinary()`, from `TTIFFDocument::getReservedSpaces()`; the pin predicate is the single `TTIFFDocument::isPinned()` that compose's `collectPins()`/`layoutIfd()` also use, so the list never drifts from what the writer pins) and `toReservedSpaceStream(mode)`/`toFreeSpaceStream()`, which wrap the composed bytes in `Prado\IO\Stream\TReservedSpaceStream` (Clip/Fail/Skip) or `TFreeSpaceStream`. No new stream class and no framework change — the decorators own the write-through mechanics, the extension only supplies the offsets. Only a **parsed** maker note has an offset to pin, so a freshly-built one reserves nothing.
- Error codes (keys) and messages live in `config/errorMessages.txt`. Both it and the class map are registered by **Composer** from `composer.json` `extra.prado` — not by any module.
- The compression codecs implement the **framework's** `Prado\IO\Compression\ICompressor` (landed in prado master with `TCompression`); this repo does not carry its own copy of the interface.
- The classes consume the framework's IO stream layer (`TStream`, `Prado\IO\Stream\TLimitStream`, `TResourceType`). It is in `pradosoft/prado` **master** but not in a tagged release, so the dev requirement is plain `^4.4`: `prado` aliases `dev-master` to `4.4.x-dev` through its `branch-alias`, and `minimum-stability: dev` + `prefer-stable` let that satisfy the constraint today and hand over to the 4.4 release the moment it is tagged. Composer fetches the framework itself — there is **no path repository**.
- PSR-7/resource IO is uniform via `TStreamIOTrait` (`writeTo()` + `sourceBytes()`): every container and metadata class accepts a `StreamInterface` (incl. `TBinaryStream`/`TLimitStream` decorators) or a PHP stream resource in `fromStream()` and writes to either via `writeTo()`. New composable classes should use the trait rather than hand-rolling stream plumbing.
- The parse/compose cores stay string-based on purpose (measured ~25x faster than per-field stream reads for TIFF's random-access pattern); `TBinaryStream` is used where it genuinely fits — the lazy metadata scan (`TTIFFDocument::scanStream()`, `TEXIF::scanFile()/scanStream()`) that seeks through huge TIFFs without reading strip data. A scanned document (`getIsScanned()`) has no captured strip blocks and no raw TIFF bytes, so absolute-offset makernotes (Canon) decode inline values only.
- Raster conversion is dual-backend through `TImageGraphics`, a routing facade: it resolves an `IImageGraphicsLibrary` (`TImageGraphicsGD` / `TImageGraphicsImagick`) from the image's own type, or from a `TImageGraphicsMode` name for the methods that create one (GD preferred, Imagick fallback), and delegates. Never call GD or Imagick functions directly in the metadata classes — go through the facade. A new primitive is added to the interface and implemented in **both** backends; a backend-only ability is declared as an `IImageGraphicsLibrary::Capability*` and gated with `TImageGraphics::supports()`, not with an `instanceof`. Every `Capability*` must have an operation behind it: `encode()` covers Jpeg/Png/WebP, `get/setICCProfile()` covers ICCEmbed, `transformICCProfile()` covers ICCTransform, `cmyk/fromCmykPixels()` covers Cmyk. `HighBitDepth` is the one deliberate exception — a selection fact with no operation, because GD is 8-bit per channel and any "support" would be a lie; callers pick a library with `getCapableLibrary()` instead.
- GD reaches parity with Imagick in software where that is honest: `TICCTransform` performs matrix/TRC ICC conversions in pure PHP off `TICCProfile`'s parsed colorants and curves, and the CMYK separation is arithmetic. Both live in `Prado\IO\Image\ICC\` — the parsed document and the compiled transform together, the way `Image\TIFF\` holds `TTIFFDocument` beside `TTIFFRaster`. `TICCProfile` keeps the header as **raw 128 bytes** and splices setters into it (`writeHeader()`), so reserved and unmodelled fields survive a rewrite byte-for-byte; it does not decompose the header into properties. It also carries its own dependency-free UTF-16 codec for `mluc` tags rather than requiring ext-mbstring. A parsed profile keeps its stored profile id and an edited one drops it (all-zero, which the spec allows) — the digest is only recomputed when `computeProfileId()` is called explicitly, so a rewrite is never silently re-digested. Lookup-table profiles (`getIsLutBased()` — CMYK and printer profiles) are **not** evaluated: they return false/null so the caller falls back to Imagick, and must never be approximated.
- `ext-gd` generates the unit tests' raster fixtures in memory, `tests/test_tools/ContainerFixtures.php` builds minimal AVI, HEIF, MP4 and JPEG XL bytes for the tests that need *a file of that format* rather than one of a particular shape (spelled as format literals, not as the constants of the classes under test, so a fixture cannot agree with a typo in one of them), and `tests/test_tools/ICCProfileBuilder.php` (both loaded by the phpunit bootstrap) builds real sRGB/Adobe-RGB/CMYK-LUT profiles the same way — no binary fixtures in the repo; the Imagick-path tests `markTestSkipped` when `ext-imagick` is absent — never let a test hard-fail on a missing optional extension.
- This is a new, pre-release codebase with no published API to preserve: **backward compatibility is not a constraint** — prefer the better design.

## Checks (all must pass before commit)

```sh
php -l <file>                                        # syntax
vendor/bin/php-cs-fixer fix src   (and: fix tests)   # style (tabs; run src and tests separately)
vendor/bin/phpstan analyse --memory-limit=1G         # static analysis (level 4)
composer unittest                                    # tests (phpunit --testsuite unit)
```

Coverage is gated, not merely reported: `tests/test_tools/coverage-gate.php` reads a clover
report and requires **every** source file to be fully covered except the three whose remaining
lines are unreachable from a test (counted, not line-numbered, so edits above them do not
break the gate; the reasons are in AGENTS.md). CI runs it on the jobs that load **both** GD
and ImageMagick, since the GD-only job cannot reach the Imagick backend:

```sh
XDEBUG_MODE=coverage vendor/bin/phpunit --testsuite unit --coverage-clover build/logs/clover.xml
php tests/test_tools/coverage-gate.php build/logs/clover.xml
```

Branch coverage is gated separately and more deeply: `tests/test_tools/branch-gate.php` reads a
`--path-coverage` report and requires every branch to be taken except the documented unreachable
edges. It runs in the `branches` job of `.github/workflows/prado-image.yml` on pull requests
and main, not on every push, because instrumenting every branch is far slower than the suite:

```sh
XDEBUG_MODE=coverage php -d memory_limit=10G vendor/bin/phpunit --testsuite unit \
    --path-coverage --coverage-php build/logs/coverage.php
php -d memory_limit=8G tests/test_tools/branch-gate.php build/logs/coverage.php
```

PHPStan runs at **level 4**, which is the level that detects branches whose condition can never
flip — dead code that full line coverage cannot reveal. The `ignoreErrors` entries in
`phpstan.neon.dist` are deliberate runtime guards, each with a comment saying why it stays;
unmatched entries are reported, so they cannot go stale. The three knowingly-unreachable
lines are listed in AGENTS.md — cover new code with tests, not with `@codeCoverageIgnore`.

See [AGENTS.md](AGENTS.md) for the full coding standards, framework conventions, and safeguards.
