# prado-image

A PRADO 4 extension providing image container readers, metadata editing, and image codecs: JPEG, TIFF, PNG, WebP/RIFF, and GIF87a/89a (animation, frames, palettes) containers; EXIF (full TIFF/IFD engine, every DC-008-2026 tag (220 known tags: the spec's 212 plus the TIFF document/host and Windows XP* fields) through Exif 3.1 (CIPA DC-008-2026, spec linked from agents/README.md) incl. the UTF-8 field type, GPS, IFD1 thumbnails, Kodak APP3 Meta) with makernote decoding for 13 camera makers; DOM-backed XMP (full ISO 16684-1 value grammar, extended XMP in JPEG, PNG/WebP/TIFF carriers); the complete Photoshop 8BIM IRB; IPTC (IIM) records; JFIF/JFXX thumbnails; PrintIM; APP12 Picture Info; the Photoshop File Info 22-field sync layer; JUMBF/APP11 box metadata; Exif WAVE audio files; fully read-write ICC profiles (`TICCProfile`: every header field, typed tag reads and writes, profile-id digest) with a pure-PHP matrix/TRC color transform (`TICCTransform`) — reading and rewriting the container without re-encoding the pixels — plus the LZW/GIF-LZW/PackBits/horizontal-predictor codecs (`Prado\IO\Compression`) and dual GD/ImageMagick raster conversion (`TImageGraphics`).

## Version

- **Current version: v1.0.0** (initial release).

## Key facts

- Classes live under `Prado\IO\Image\`, `Prado\IO\Image\TIFF\`, `Prado\IO\Image\GIF\`, `Prado\IO\Image\ICC\`, `Prado\IO\Image\Meta\`, `Prado\IO\Image\Meta\Makernote\`, and `Prado\IO\Compression\` (PSR-4 `Prado\` → `src/`). This extension does **not** update the framework's `classes.php`; Prado3 short names come from `config/classMap.json`.
- `TEXIFTags`, `TMakernoteTags`, `TMakernoteTables`, and `TPhotoshopResourceNames` embed large fact tables (tag ids, names, enumeration lookups, maker header signatures) sourced from the public TIFF/EXIF/GPS specs and camera documentation; edit them like any source file (there is no build step), but keep entries factual and complete.
- EXIF rewriting pins the makernote value area at its original offset (`TTIFFTag::setPreserveOffset()`), so camera-internal absolute pointers survive; never break that invariant.
- TIFF files are read-write: strip/tile data rides `TTIFFTag::setExternalData()` (captured on parse, relocated on compose with the byte-counts pair kept in sync); `TTIFF::getImage()/setImage()` decode/encode the raster through the `Prado\IO\Compression` codecs, including the CCITT fax modes (`TCCITTFaxCompressor`). Decoding lives in `TTIFFRaster::toRgb()` — strips and tiles, chunky and planar, 1/2/4/8/16-bit, either fill order, and the bilevel/grayscale/palette/RGB/CMYK/YCbCr/L\*a\*b\* photometrics, all normalized to 8-bit RGB; the writer always emits 8-bit chunky RGB strips (or 1-bit bilevel for the fax modes). The TIFF 6.0 section-by-section status lives in `agents/working/TIFF6-coverage.md` (spec PDF linked from `agents/README.md`; local copy in the git-ignored `local/`).
- XMP property forms come from `TXMPSchemas`, not from the caller: `TXMP::setProperty()`/`addArrayItem()` consult it to write `dc:title` as a LangAlt and `dc:subject` as a `Bag`, and `TXMP::validate()` reports stored forms that contradict the schema. Extend that table when adding schema knowledge rather than special-casing names in `TXMP`.
- Every container is read **and** write for each carrier its format defines, and a setter must never accept data it will drop: JPEG (APP1/APP2/APP13 segments), TIFF (IFD tags), PNG (`iCCP`, `eXIf`, `iTXt` XMP, and the `Raw profile type 8bim` text chunk that carries the Photoshop IRB and so IPTC), WebP (`ICCP`, `EXIF`, `XMP ` with their `VP8X` flags), GIF (`XMP DataXMP`, `ICCRGBG1012`, comments, the NETSCAPE2.0 loop count). `TImageFile::hasIPTC()/hasICCProfile()` go through the accessors so a container can override them. Where a format has no carrier at all — IPTC in WebP and GIF — the setter **throws** rather than silently discarding; `TContainerReadWriteTest` is the regression guard for the whole matrix.
- GIF is read-write and animation-aware: `TGIF` walks the block stream into an ordered list of `TGIFFrame`s and `TGIFExtension`s (`Prado\IO\Image\GIF\`), and composes it back byte-faithfully. Frames are **authored, never coalesced** — the stored sub-rectangle, interlace flag, local colour table, delay, disposal, and transparent index are kept as read, because coalescing is exactly what loses them (measured: ImageMagick's coalesce/deconstruct path rewrites frame geometry, disposal, background index, and transparency). Two invariants matter: data sub-block *framing* is preserved, not just the joined bytes; and application-extension identities keep their exact case, so `XMP DataXMP` and `ICCRGBG1012` survive (ImageMagick lowercases them, and GD drops every extension along with all frames after the first). `TGIFFrame::setPixels()` raises the LZW minimum code size to fit the indexes; pixel data rides `TGIFLZWCompressor` and raster conversion goes through `TImageGraphics`, including `paletteQuantize()` for `setImage()`/`TGIF::fromImage()` (both keep every extension and replace only the frames). A third invariant: the `XMP DataXMP` packet is stored **raw**, not in sub-blocks, ended by `TGIFExtension::MagicTrailer` (258 bytes: 1, then 255 down to 1, then two zeros) — `TGIF::parseRawApplication()` special-cases it on read and `TGIFExtension::getIsRaw()` on write, because sub-block framing would eat one packet byte per 255 as a length. ICC rides `ICCRGBG1012` in ordinary sub-blocks; there is no IPTC carrier, so `setIPTC()` throws.
- PNG is animation-aware (APNG): `TPNG` reads/writes `acTL`/`fcTL`/`fdAT` as `TAPNGFrame`s (`Prado\IO\Image\PNG\`) over the generic chunk model — `getApngFrames()`/`setApngFrames()`/`addApngFrame()`/`fromApngImages()`, with `getApngFrameImage()` decoding a frame by rebuilding a standalone PNG from its data + IHDR colour fields. Frames are authored, not composited; a no-edit round trip is byte-faithful. `setApngFrames()` rebuilds the chunk region with **one ascending sequence number across every fcTL and fdAT** (the invariant a decoder validates) and sets the canvas from the frames' placed extents. Position-sensitive chunks (acTL/fcTL before IDAT, fdAT after, cICP/mDCv/cLLi before PLTE) are in `TPNG::ChunkOrder` so fresh authoring lands them validly. `setImage()` re-encodes to a still PNG (animation dropped).
- Privacy scrubbing is metadata-wide and first-class: `IPrivacyScrubbable::clearPrivateData(int $types = TPrivacyCategory::All): int` is implemented by every carrier (`TEXIF`, `TXMP`, `TIPTC`, `TPhotoshopIRB`) and by `TImageFile`, whose fan-out reaches every carrier the container holds (getter/setter pairs) plus a `clearFormatPrivateData()` hook for format-only fields (JPEG comment/JFIF/JFXX/PictureInfo, PNG text chunks, GIF comments; TTIFF scrubs its live EXIF there since it has no `setEXIF()`). `TPrivacyCategory` (`Prado\IO\Image\`) is a `TEnumerable` of one bit per identifying category (`All` = -1) and its docblock tabulates what each flag removes per carrier. The per-category fact lists are constants beside each carrier — `TEXIF::PrivacyTags` ([group, id] pairs), `TXMP::PrivacyProperties` ([namespace, property]), `TIPTC::PrivacyDatasets`, `TPhotoshopIRB::PrivacyResources`; EXIF's directory-level categories (Location = GPS IFD via its pointer tag, MakerNote, Thumbnail = whole IFD1, Interoperability) are removed structurally and no IFD is ever created as a side effect. It **never** touches picture-describing fields (exposure/colour/dimensions) — a scrubbed file must stay a useful photo. The IRB redacts (not drops) its embedded IPTC, and the IPTC scrub replaces an existing mandatory envelope date (`DateSent`) with `TIPTC::ScrubbedDate` and re-derives an existing `EnvelopeNumber` from it (counted as removals) because `validate()` would otherwise re-stamp today's date on the next `toBinary()` — replaced, never minted: a record set with no envelope is not given one. A scrub must be idempotent and must not mint new identifiers or timestamps. When adding a tag/property that carries identifying data, add it to the carrier's list under the right category; `TEXIFPrivacyTest`/`TPrivacyScrubTest` enforce per-flag isolation for each carrier and that each container's scrub reaches every carrier it has.
- Private spaces (maker notes, private IFDs) bridge to the framework's reserved-space stream decorators: `TEXIF`/`TTIFF` expose `getReservedSpaces()` (the pinned `[offset,length]` ranges within `toBinary()`, from `TTIFFDocument::getReservedSpaces()`; the pin predicate is the single `TTIFFDocument::isPinned()` that compose's `collectPins()`/`layoutIfd()` also use, so the list never drifts from what the writer pins) and `toReservedSpaceStream(mode)`/`toFreeSpaceStream()`, which wrap the composed bytes in `Prado\IO\Stream\TReservedSpaceStream` (Clip/Fail/Skip) or `TFreeSpaceStream`. No new stream class and no framework change — the decorators own the write-through mechanics, the extension only supplies the offsets. Only a **parsed** maker note has an offset to pin, so a freshly-built one reserves nothing.
- Error codes (keys) and messages live in `config/errorMessages.txt`. Both it and the class map are registered by **Composer** from `composer.json` `extra.prado` — not by any module.
- The compression codecs implement the **framework's** `Prado\IO\Compression\ICompressor` (landed in prado master with `TCompression`); this repo does not carry its own copy of the interface.
- The classes consume the framework's IO stream layer (`TStream`, `Prado\IO\Stream\TLimitStream`, `TResourceType`). It is in `pradosoft/prado` **master** but not in a tagged release, so the dev requirement is `^4.4 || dev-master` (with `minimum-stability: dev` + `prefer-stable`) and Composer fetches the framework itself — there is **no path repository**; `prado` declares no `branch-alias`, which is why `dev-master` has to be named explicitly rather than being covered by `^4.4`.
- PSR-7/resource IO is uniform via `TStreamIOTrait` (`writeTo()` + `sourceBytes()`): every container and metadata class accepts a `StreamInterface` (incl. `TBinaryStream`/`TLimitStream` decorators) or a PHP stream resource in `fromStream()` and writes to either via `writeTo()`. New composable classes should use the trait rather than hand-rolling stream plumbing.
- The parse/compose cores stay string-based on purpose (measured ~25x faster than per-field stream reads for TIFF's random-access pattern); `TBinaryStream` is used where it genuinely fits — the lazy metadata scan (`TTIFFDocument::scanStream()`, `TEXIF::scanFile()/scanStream()`) that seeks through huge TIFFs without reading strip data. A scanned document (`getIsScanned()`) has no captured strip blocks and no raw TIFF bytes, so absolute-offset makernotes (Canon) decode inline values only.
- Raster conversion is dual-backend through `TImageGraphics`, a routing facade: it resolves an `IImageGraphicsLibrary` (`TImageGraphicsGD` / `TImageGraphicsImagick`) from the image's own type, or from a `TImageGraphicsMode` name for the methods that create one (GD preferred, Imagick fallback), and delegates. Never call GD or Imagick functions directly in the metadata classes — go through the facade. A new primitive is added to the interface and implemented in **both** backends; a backend-only ability is declared as an `IImageGraphicsLibrary::Capability*` and gated with `TImageGraphics::supports()`, not with an `instanceof`. Every `Capability*` must have an operation behind it: `encode()` covers Jpeg/Png/WebP, `get/setICCProfile()` covers ICCEmbed, `transformICCProfile()` covers ICCTransform, `cmyk/fromCmykPixels()` covers Cmyk. `HighBitDepth` is the one deliberate exception — a selection fact with no operation, because GD is 8-bit per channel and any "support" would be a lie; callers pick a library with `getCapableLibrary()` instead.
- GD reaches parity with Imagick in software where that is honest: `TICCTransform` performs matrix/TRC ICC conversions in pure PHP off `TICCProfile`'s parsed colorants and curves, and the CMYK separation is arithmetic. Both live in `Prado\IO\Image\ICC\` — the parsed document and the compiled transform together, the way `Image\TIFF\` holds `TTIFFDocument` beside `TTIFFRaster`. `TICCProfile` keeps the header as **raw 128 bytes** and splices setters into it (`writeHeader()`), so reserved and unmodelled fields survive a rewrite byte-for-byte; it does not decompose the header into properties. It also carries its own dependency-free UTF-16 codec for `mluc` tags rather than requiring ext-mbstring. A parsed profile keeps its stored profile id and an edited one drops it (all-zero, which the spec allows) — the digest is only recomputed when `computeProfileId()` is called explicitly, so a rewrite is never silently re-digested. Lookup-table profiles (`getIsLutBased()` — CMYK and printer profiles) are **not** evaluated: they return false/null so the caller falls back to Imagick, and must never be approximated.
- `ext-gd` generates the unit tests' image fixtures in memory and `tests/test_tools/ICCProfileBuilder.php` (loaded by the phpunit bootstrap) builds real sRGB/Adobe-RGB/CMYK-LUT profiles the same way — no binary fixtures in the repo; the Imagick-path tests `markTestSkipped` when `ext-imagick` is absent — never let a test hard-fail on a missing optional extension.
- This is a new, pre-release codebase with no published API to preserve: **backward compatibility is not a constraint** — prefer the better design.

## Checks (all must pass before commit)

```sh
php -l <file>                                        # syntax
vendor/bin/php-cs-fixer fix src   (and: fix tests)   # style (tabs; run src and tests separately)
vendor/bin/phpstan analyse --memory-limit=1G         # static analysis (level 4)
composer unittest                                    # tests (phpunit --testsuite unit)
```

Coverage is gated, not merely reported: `tests/test_tools/coverage-gate.php` reads a clover
report and requires **every** source file to be fully covered except the four whose remaining
lines are unreachable from a test (counted, not line-numbered, so edits above them do not
break the gate; the reasons are in AGENTS.md). CI runs it on the jobs that load **both** GD
and ImageMagick, since the GD-only job cannot reach the Imagick backend:

```sh
XDEBUG_MODE=coverage vendor/bin/phpunit --testsuite unit --coverage-clover build/logs/clover.xml
php tests/test_tools/coverage-gate.php build/logs/clover.xml
```

PHPStan runs at **level 4**, which is the level that detects branches whose condition can never
flip — dead code that full line coverage cannot reveal. The `ignoreErrors` entries in
`phpstan.neon.dist` are deliberate runtime guards, each with a comment saying why it stays;
unmatched entries are reported, so they cannot go stale. The five knowingly-unreachable
lines are listed in AGENTS.md — cover new code with tests, not with `@codeCoverageIgnore`.
